# 企业内部知识库问答助手

一个基于大模型 API 的小工具，解决一个很具体的问题：公司制度、产品手册这类文档散在共享盘里，
同事问一句"出差住宿能报多少"要翻半天。这个工具把文档变成可以提问的知识库。

顺带做了第二件事：把销售 CSV 变成一份可以直接贴进周会文档的周报。

## 功能

| 命令 | 作用 |
| --- | --- |
| `python src/main.py ask "问题"` | 检索文档 → 拼 Prompt → 调模型 → 回答并标注来源 |
| `python src/main.py report` | 读 CSV → 本地统计 → 调模型写周报 → 输出 Markdown |
| `python src/main.py eval` | 跑测试集，统计检索命中率 |
| `python src/main.py logs` | 看历史问答，找出检索质量低的问题 |
| `python src/main.py check` | 配好 key 后自检，确认模型连通 |

## 快速开始

不需要装任何第三方包，Python 3.8 以上直接跑。

```
# 1. 配置模型（不配也能跑，会进模拟模式）
copy config.example.json config.json
# 编辑 config.json，填入 api_key

# 2. 先确认能通
python src/main.py check

# 3. 试一下
python src/main.py ask "出差住宿费标准是多少"
python src/main.py report
python src/main.py eval
```

### 用哪个模型：选一个永久免费的

默认配置对的是**智谱 GLM-4-Flash**，注册后永久免费、128K 上下文，中文问答够用。

| 平台 | 免费政策 | base_url | model |
| --- | --- | --- | --- |
| 智谱（推荐） | GLM-4-Flash 永久免费 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 硅基流动 | 9B 以下模型永久免费 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| DeepSeek | 新用户送额度，之后很便宜 | `https://api.deepseek.com` | `deepseek-chat` |

三家都是 OpenAI 兼容格式，**只改 config.json 里两个字段，代码一行不用动**——
这也是为什么 `llm.py` 里把 `base_url` 和 `model` 做成配置项而不是写死。

申请步骤（智谱，约 3 分钟）：
1. 打开 `open.bigmodel.cn`，手机号注册
2. 控制台左侧「API Keys」→ 新建，复制
3. 粘进 `config.json` 的 `api_key` 字段
4. `python src/main.py check` 确认返回正常

## 检索是怎么做的

没有用向量数据库，用的是最朴素的方案，原因写在下面。

1. 按空行把每份文档切成段落，**并把每段所属的小标题拼回段首**（原因见下面的踩坑记录）
2. 把问题和一个段落都切成**字符二元组**（`报销标准` → `报销`、`销标`、`标准`）
3. 相似度 = 共有的二元组数 ÷ 问题的二元组总数
4. 取相似度最高的 2 段，拼进 Prompt
5. 提示词里明确要求"只能依据提供的资料回答，没有就说不知道"

不用向量库，是因为四个字的理由：**先跑通再优化**。装 embedding 模型、建索引、维护向量库，
在这个体量下（4 份文档 / 30 个段落）收益还不如把 Prompt 写好。

## 效果测试

我自己标了两组测试集，跑出来是这样：

| 测试集 | 条数 | 检索命中率 |
| --- | ---: | ---: |
| 规范表述（`questions.json`） | 20 | 100% |
| 口语化（`questions_colloquial.json`） | 12 | 91.7% |

**规范表述那组 100% 说明不了什么**——题目是照着文档写的，用词高度重合，等于开卷考试。
真正有信息量的是口语化那组。

第一版跑出来只有 83.3%，掉下来的 3 条里有一条帮我找到了真正的设计缺陷：

**踩坑：切块时把标题丢了，段落就检索不到**

> 问："出差住宿费标准是多少"
> 结果：模型回答"资料中未提及"

`住宿标准` 这个小标题下面是这么写的：

```
## 住宿标准
住宿费按城市分级限额……
一线城市（北京、上海、广州、深圳）每晚上限 500 元……
```

第二段里**一个"住宿"、一个"标准"都没有**，全在标题里。我按空行切段落时把标题扔了，
这一段跟问题的二元组重合数是 0，连候选都进不去，模型当然只能说不存在。

改法很简单：切块时把每个段落所属的小标题拼回段首。改完之后这段排到第 2 位，
口语化命中率从 83.3% 升到 91.7%，答案也正确了。

**这件事的教训比分数重要**：RAG 里"切块策略"不是细节，切错了后面全白搭。

**剩下那 1 条失败是硬伤：同义表达没有交集**

> 问："买回来不喜欢能退吗"
> 结果：无命中

文档写的是"无理由退货"，"不喜欢"和"无理由"没有任何二元组重合。字面匹配天生处理不了这个，
得靠同义词表或者 embedding。这条我留着没修，因为它标出了这个方案的边界。

## 踩过的坑

**1. 让模型算数，它真的会编**
第一版把 CSV 原始数据整个丢给模型，让它自己算总额和占比，结果数字对不上。
后来改成先在本地算完统计，只把结果交给模型组织语言。**数字归代码，文字归模型。**

**1.5 就算给了算好的数字，它还会自己换算单位**
改成"本地算好再给它"之后，生成的第一版周报里写着"西南区域表现较弱，仅 4.79 万元"，
而实际是 478500 元 = **47.85 万**，差了十倍。它没算错加法，是在"元→万元"这一步换算错了。
最后在 Prompt 里加了硬性要求：**数字直接引用原文，不许做单位换算**，并额外把占比一起算好喂给它。
改完数字全对。教训是：**别指望模型在数字上不出错，只能把它的自由裁量空间压到零。**

**2. 不设阈值的话，什么都像答案**
刚开始只要有一个二元组重合就返回，问"今天天气"也能匹配到考勤制度里的一段。
加了 0.08 的分数门槛后噪声明显少了，但代价是长问题容易被误杀（见上面失败 1）。

**3. Windows 下 CSV 第一列读出乱码**
用 Excel 另存的 CSV 带 BOM，直接 `utf-8` 读会在第一列开头多出 `\ufeff`，
`DictReader` 拿到的字段名变成 `\ufeffmonth`，`row["month"]` 直接 KeyError。
改用 `encoding="utf-8-sig"` 解决。

**4. 没配 key 就崩，没法演示**
面试或者换台机器演示时不可能随身带 key。加了一个模拟模式：检测不到 key 就返回占位回答，
流程照样走得通，只是内容是假的。**演示能跑通，比参数好看重要。**

## 已知限制

- 只支持 `.md` 文档，不解析 PDF 和 Word。真实企业场景这两个才是大头。
- 检索是字面匹配，同义词、简称、错别字都处理不了。
- 没有做多轮对话，每次提问都是独立的。
- 报表只支持固定格式的 CSV，列名写死在代码里。
- 没有权限控制，任何人跑起来都能看到全部文档。
